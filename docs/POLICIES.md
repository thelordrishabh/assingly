# MVP policy defaults

Each accepted contract snapshots its terms: later configuration changes do not
rewrite a live contract. A writing reward is divided in integer Dime by assigning
the remainder to the earliest page numbers. For each payable allocation, the late
discount is `min(50, 10 * startedDaysLate)` percent, with a 24-hour grace period
before a requester can perform an eligible full-refund late cancellation.

A cancellation is a full refund only before a writer accepts, or after the grace
period when no page has been submitted and no physical handoff started. Submitted
or handed-off work is reviewed per page. An inconclusive moderator decision uses
the documented 50/50 allocation unless the moderator records a different supported
completion percentage.

Reliability is event-based, separate from the wallet, and only changes for a
recorded substantiated failure or deliberate misuse. Spending Dime, ordinary
disputes, and inconclusive outcomes do not lower it. The current pilot threshold
flags repeated substantiated issues for moderator review; it never permanently
restricts an account automatically.

Academic-integrity boundaries: Assingly permits copying complete, authorized source
material only. It strictly prohibits requests to solve problems, create original
answers, complete examinations, or produce work for submission.

Dime boundaries & disabled merchant seam: Dime is an internal, non-cashable unit
with zero monetary value. Real-money transactions, cash-outs, and bank integrations
are strictly prohibited. Merchant redemption is an architectural seam disabled by default
with no active API or user interface.

Private source and evidence are retained for 180 days after closure unless a report,
appeal, or audit obligation is active. Source text, page images, and handoff codes
are not included in notifications or analytics. Demo uploads remain on the local
developer's machine.
